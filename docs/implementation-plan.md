# MVP implementation plan

The [interactive prototype](prototype/README.md) exercises the review flow with sample data. Use the [publication rules](publication-rules.md) when implementing the real client and server. Each unchecked stage describes future implementation work.

- [ ] **1. Prove the provider path.** Run the [integration experiment](../backend/README.md) and record reproducible, anonymized samples. Pass when one verified Steam identity and one IGDB game resolve to the same Steam library entry, with the expected minutes. Document what a private library returns.
- [ ] **2. Build a public vertical slice.** Scaffold one Flutter project for Android and web. Create the initial PostgreSQL schema on Supabase with a versioned migration, import a small catalog sample and expose guest search. Pass when both clients open the same game ID, and a copied game URL survives a fresh browser session and reload.
- [ ] **3. Link a player and show their library.** Add service accounts, Steam linking, server-side refresh and the ready-to-rate list. Exercise 0, 89 and 90 minutes, a missing game, hidden hours and a failed sync. Pass when each case gives the player the appropriate action and one account cannot claim another account's linked Steam identity.
- [ ] **4. Draft and publish a rating.** Save a private draft at 89 minutes on Android and reopen it on web. Verify another account cannot read it. At 90 minutes, verify the draft stays private until the author chooses a score and publishes. Exercise publication with each play status and with the field blank. Test 0, 0.5 and 10, an out-of-range score, failed and duplicate submissions, edits and deletion. Pass when a guest can open the published URL and both clients show the same score, status and playtime snapshot.
- [ ] **5. Complete public discovery.** Add author pages, game averages and distributions. Verify that editing replaces the original vote, deletion removes it and an empty game has no average. Check spoiler reveal, keyboard navigation and library privacy as a guest.
- [ ] **6. Validate a release candidate.** Run formatting, analysis and tests, build the web and Android targets, then exercise a hosted web build and a physical Android device. Follow one user from registration through Steam linking to sharing a review with a signed-out reader. Document the actual local setup, deployment and provider configuration used.
